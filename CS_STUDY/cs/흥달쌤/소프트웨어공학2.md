## 객체지향 설계

### 객체지향 구성 요소
- 클래스: 속성과 연산을 정의해서 만든 틀
- 객체: 클래스의 인스턴스
- 속성: 객체들이 가지고 있는 고유한 데이터
- 메서드: 작업을 수행하기 위한 명령문의 집합
- 메시지: 객체에게 어떤 행위를 하도록 지시

### 객체지향 언어의 특징
- 캡슐화: 속성과 메서드를 하나로 묶은것
- 정보은닉: 내부 데이터에 직접 접근할 수 없도록 제한
- 상속: 상위 클래스의 속성과 메서드를 하위 클래스가 물려받는것
- 다형성: 하나의 메시지에 대해 여러가지 방법으로 응답
- 추상화: 실체의 핵심적인 개념만을 추출

### 객체지향 설계 원칙(SOLID)
- 단일책임 원칙: 한 클래스는 하나의 책임만 가져야함
- 개방 폐쇄 원칙: 확장에 열려있고, 수정에 닫혀있어야 한다
- 리스코프치환원칙: 자식 클래스는 언제나 자신의 부모 클래스를 대체
- 인터페이스 분리 원칙: 사용하지 않는 인터페이스는 구현하지 말아야 한다.
- 의존성 역전 원칙: 변화가 거의 없는것에 의존

### GOF 디자인 패턴

## 애플리케이션 테스트케이스 설계

### 소프트웨어 테스트
- 결함을 발견하기 위한 절차와 행위
- 테스트의 필요성
    - 오류 발견관점
    - 오류 예방관점
    - 품질 향상관점
- 테스트의 기본원칙
    - 결합집중: 파레토 법칙
    - 살충제 패러독스: 새로운 테스트 케이스 설계
    - 오류-부재의 궤변: 사요자의 요구사항을 충족해야한다. 

### 테스트 오라클
- 테스트 결과가 올바른지 판단하기 위해 사전에 정의된 참값과 비교하여 검증하는 기법
- 유형
    - 참 오라클: 모든 입력값 테스트
    - 샘플링 오라클: 제한된 입력만 테스트
    - 휴리스틱 오라클: 특정 입력값 외에 추정결과를 제공
    - 일관성 검사 오라클: 소프트웨어 변경 전후의 결과 비교

### 테스트 레벨
- 단위 테스트: 모듈검증
- 통합테스트: 인터페이스 검증
- 시스템테스트: 요구 분석 검증
- 인수테스트: 알파&베타

### 화이트박스 테스트
- 소프트웨어의 내부 구조와 동작을 검사
- 기법
    - 문장 검증: 모든 문장을 수행
    - 선택 검증:
    - 경로 검증:
    - 조건 검증:
- 기초경로검사
    - V = E-N+2

### 블랙박스 테스트
- 프로그램의 사용자 요구사항 명세를 보면서 테스트
- 기법
    - 동등 분할기법: 입력 자료에 초점을 맞춘 테스트
    - 경계값 분석: 경계값을 테스트 케이스로 선정
    - 원인-효과 분석: 입력 데이터 간의 관계와 출력에 영향을 미치는 상황을 분석
    - 오류 예측 검사: 과거의 경험이나 테스터의 감각으로 테스트
    - 비교 검사: 여러버전의 프로그램에 동일한 자료를 제공
    - 상태전이 검사: 상태를 변화시키는 이벤트와 입력값을 파악

### 테스트 목적에 따른 분류

- 안전: 보안적인 결함을 점검

- 테스트를 얼마나 수행했는지 측정하는 기준

- 0: 불안정 단계: 미구현 또는 목표 미달성

- 구성
    - 콘텐츠 제공자
    - 콘텐츠 분배자
    - 패키저
    - 보안 컨테이너
    - DRM 컨트롤러
    - 클리어링 하우스

### 저작권 보호 기술

- 위변조 방지: 콘텐르에 무단 조작 시 감지하고 오류동작을 유발
