# UML

## 구조 다이어그램

### 클래스 다이어그램
- 시스템의 구조를 나타내는데 사용된다.
- 클래스, 속성, 메서드, 객체 간의 관계등을 시각적으로 표현한다.
- 클래스와 클래스 사이의 관계를 나타내는 정적인 모델
- 클래스, 속성, 메서드, 관계

### 객체 다이어그램
- 시스템의 특정 시점에서 객체와 객체간의 관계를 나타내는데 사용
- 객체는 클래스의 인스턴스이며, 관계는 객체간의 상호작용 나타냄
- 특정 시간에 시스템의 동적인 면

### 컴포넌트 다이어그램
- 컴포넌트와 그들 간의 관계를 나타낸다.

### 배치 다이어그램
- 시스템을 구성하는 하드웨어 요소와 네트워크 요소, 그들간의 관계를 나타낸다.

### 복합체 구조 다이어그램
- 클래스의 내부 구조를 구체적인 수준에서 시스템의 실행 구조 설명

### 패키지 다이어그램
- 소프트웨어 시스템을 구성하는 패키지 및 패키지간의 관계를 나타낸다.
- 논리적으로 묶인 요소들을 그룹화하는 단위

## 행위 다이어그램

### 유스케이스 다이어그램
- 시스템의 기능과 사용자 간의 상호작용을 나타낸다.
- 시스템의 외부 관점에서 기능들을 표현한다.

### 순차 다이어그램
- 시스템의 객체들 간의 상호작용을 시간 순서에 따라 나타냄

### 커뮤니케이션 다이어스램
- 시스템 내부 또는 시스템 간의 통신을 나타내는 데 사용

### 상태 다이어그램
- 객체의 상태와 상태 변화

### 활동 다이어그램
- 시스템의 비즈니스 프로세스 또는 워크플로를 나타내는데 사용
- 업무의 흐름을 표현

### 상호작용 다이어그램
- 시스템 내부 또는 시스템 간의 상호작용
- 객체 간의 메시지 전달

### 타이밍 다이어그램
- 시스템 내부 또는 시스템 간의 신호변화를 시간순서에 따라 나타냄

## 관계

### 일반화 관계
- 하위 클래스가 상위 클래스의 속성과 메서드를 상속하는 관계
- "IS-A"라고도 불림

### 연관 관계 ASSOCIATION
- 두개 이상의 클래스 간의 관계

### 의존관계
- 한클래스가 다른 클래스의 서비스를 사용하거나 기능에 의조낳는 관계
- 짧은 기간 동안, 한정된 상황에서만

### 실체화 관계
- 인터페이스를 구현하는 클래스의 관계

### 집약 관계
- 하나의 객체가 여러 다른 객체를 포함하는 관계

### 합성 관계
- 하나의 객체가 다른 객체를 포함하고 포함된 객체는 포함하는 객체 없이는 존재할수 없음

## 유스케이스 관계

### 연관관계
- 유스케이스와 엑터사이의 관계

### 포함관계
- 유스케이스를 수행 할때 반드시 실행되어야하는 경우

### 확장관계
- 유스케이스를 수행할때 특정 상황에서만 실행되는 경우

### 일반화관계
- 부모 유스케이스와 자식 유스케이스들 간의 관계
