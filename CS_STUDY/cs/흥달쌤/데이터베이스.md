# 데이터베이스

## 데이터베이스 개념

### 데이터베이스 정의
- 공유 데이터: 여러 응용 프로그램이 공동으로 사용
- 저장 데이터: 컴퓨터가 접근할 수 있는 매체에 저장
- 통합 데이터: 중복을 최소화하여 통합
- 운영 데이터: 조직의 목적을 달성하기 위한 데이터

### 데이터베이스 스키마
- 외부 스키마: 사용자
- 개념 스키마: 전체적인 뷰
- 내부 스키마: 저장 구조

### 데이터 독립성
- 논리적 독립성: 개념 스키마가 변경되어도 외부스키마는 변경되지 않음
- 물리적 독립성: 내부 스키마가 변경되어도 외부 및 개념 스키마는 변경되지 않음

### DBMS의 종류
- 계층형: 트리구조
- 네트워크형: 계층형 모델의 단점을 보완, 다대다 가능
- 관계형: 행과 열로 구성된 테이블 구조
- 객체지항형: 객체지향 프로그래밍 개념에 기반한 데이터베이스
- 객체 관계형: 관계형 데이터베이스에 객체지향 개념을 결합
- NoSQL: 비정형 데이터 처리에 적합
- NewSQL: 관계형 데이터베이스와 NoSQL의 장점 결합

## 논리 데이터베이스 설계

### 이상현상
- 데이터 중복으로 인해 릴레이션 조작 시 발생하는 예기치 않은 문제
- 종류
    - 삽입 이상: 불필요한 데이터까지 함께 삽입
    - 삭제 이상: 관련된 데이터가 함께 삭제
    - 갱신 이상: 속성값 일부만 갱신되어 정보 모순이 생기는 문제

### 함수적 종속
- 어떤 속성 집합이 다른 속성 집합의 값을 유일하게 결정하는 관계
- A가 B를 함수적으로 결정: A -> B
- 함수적 종속 관계
    - 완전 함수적 종속: 완전히 종속되는 경우
    - 부분 함수적 종속: 복합속성의 일부 속성만으로 종속자가 결정되는 경우
    - 이행적 함수 종속:

### 정규화
- 제 1정규형: 모든 속성값이 원자값
- 제 2정규형: 부분함수 종속 제거
- 제 3정규형: 이행한수 종속 제거
- 보이스/코드 정규형: 모든 결정자가 후보키가 되어야 하는 상태
- 제 4정규형: 다치 종속 제거
- 제 5정규형: 조인 종속 제거

### 반정규화
- 성능 향상이나 개발 및 운영의 편의성을 위해 의도적으로 중복을 제거

### 데이터베이스 이중화
- 장애에 대비하여 동일한 데이터 베이스를 중복하여 관리하는 방식
- 분류
    - Eager 기법: 트랜잭션 발생시 즉시 반영
    - Lazy 기법: 트랜잭션 완료 후 반영

### 데이터베이스 백업
- 전체 백업: 모든 제이터를 백업
- 증분 백업: 변경/추가된 데이터만 백업
- 차등 백업: 모든 변경/추가된 데이터를 백업
- 합성 백업: 전체 백업본과 증분 백업을 함하여 새로운 전체 백업 생성

### RTO/ RPO
- 복구 시간 목표(RTO)
- 복수 시점 목표(RPO)

### 데이터베이스 암호화 방식
- API방식: 애플리케이션에서 수행
- Plug-in 방식: DB서버에 제품 설치 후 수행
- TDE방식: DBMS내부의 기본 모듈로 수행

### 파티셔닝
- 데이터베이스의 특정 부분을 여러 섹션으로 분할
- 분할기준
    - 범위 분할
    - 목록 분할
    - 해시 분할
    - 라운드 로빈 분할
    - 합성 분할

### 클러스터
- 자주 사용되는 테이블의 데이터를 디스크 상 동일한 위치에 저장

### 인덱스
- 데이터베이스 테이블 검색 속도를 향상을 위한 자료구조
- 인덱스의 종류
    - 클러스터 인덱스
    - 넌클러스터 인덱스
    - 밀집 인덱스
    - 희소 인덱스

### 뷰
- 기본 테이블에서 유도된 이름이 있는 가상 테이블

### 시스템 카랄로그
- 데이터 개체들에 대한 정보를 저장한 시스템 테이블

### 절차형 SQL
- 트리거: 이벤트에 반응하도록 작성된 프로그램

## 관계 데이터베이스 모델

### 관계 데이터 릴레이션의 구조
- 속성: 릴레이션의 열, 개체의 특성을 기술
- 튜플: 릴레이션의 행, 속성 값들의 집합
- 도메인: 속성이 가질 수 있는 값의 범위
- 차수: 릴레이션의 속성의 총 개수
- 카디널리티: 릴레이션의 튜플의 총 개수

### 릴레이션의 구성
- 릴레이션 스키마
    - 릴레이션의 이름, 속성 이름, 데이터 타입등을 정의

### 관계 대수
- 원하는 데이터를 찾기 위한 절차적 언어
- 순수관계 연산자
- SELECT
- PROJECT
- JOIN
- DIVISION

### 관계 해석
- 원하는 정보가 무엇이라는 것만 정의하는 비절차적 특성
- 튜플 관계해석과 도메인 관계 해석

## 키와 무결성 제약 조건

### 키
- 튜플을 고유하게 식별하고 구별하기 위해 사용하는 컬럼
- 종류
    - 슈퍼키: 유일성
    - 후보키: 유일성+최소성
    - 기본키
    - 대체키

### 데이터 무결성 종류
- 개체 무결성: 기본키는 중복되지 않고, NULL값을 가질 수 없다.
- 참조 무결성: 외래키는 NULL이거나, 참조 릴레이션의 기본키와 일치해야 한다.
- 도메인 무결성: 속성 값은 정의된 도메인애 속해야 한다.
- 고유 무결성: 특정 속성 값은 중복되지 않고 유일해야 한다.
- 키 무결성: 릴레이션은 적어도 하나 이상의 키를 가져야 한다.

    - 병행 투명성: 동시 실행시 간섭 없이 올바르게 처리
    - 장애 투명성: 장애가 발생하도 처리

### 트랜잭션
- 데이터베이스의 상태를 변화시키는 하나의 논리적 작업 단위
- 트랜잭션 성질(ACID)
    - 원자성(Atomicity): 모두 수행되거나 전혀 수행되지 않아야 한다.
    - 일관성(Consistency)
    - 독립성/격리성(Isolation): 트랜잭션간에 간섭이 있으면 안됨
    - 영속성(Durability): 결과가 영구적으로 반영되어야 한다

### 트랜잭션 상태
- 활동
- 실패
- 철회
- 부분 완료
- 완료

### 병행제어
- 트랜잭션 동시 실행시, 일관성을 유지하도록 하는 기법
- 병행제어 안할 때 문제점
    - 갱신 분실
    - 비완료 의존성
    - 모순성
    - 연쇄 복귀
- 병행제어 기법
    - 로킹
    - 2단계 로킹 규약
    - 타임스탬프
    - 낙관적 병행제어
    - 다중 버전 병행 제어

### 회복기법
- 로그기반 회복 기법
    - 지연갱신: REDO만 실행
    - 즉시 갱신: REDO, UNDI 모두 실행
- 검사점 회복기법
