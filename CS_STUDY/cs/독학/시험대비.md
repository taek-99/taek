# 시험대비

## 결합도

- 자료(Data): 값 전달, 결합도 제일 낮음
- 스탬프(Stamp): 배열, 오브젝트 전달
- 제어(Control): 제어요소 전달
- 외부(External): 다른 모듈에서 만든 변수 참조
- 공통(Common): 전역변수
- 내용(Content): 모듈내부 변수 기능 사용

## 응집도

- 우연적 응집도(Coincidental): 모듈 내부의 각 구성들이 연관이 없을경우
- 논리적 응집도(Logical): 유사한 성격을 갖거나 특정하게 분류되는 처리 요소
- 시간적 응집도(Temporal): 같은 시간에 수행, 특정 시간해 처리
- 절차적 응집도(Procedural): 관련된 기능들을 순차적으로 수행
- 통신적 응집도(Communication): 동일한 입력, 출력
- 순차적 응집도(Sequential): 출력값을 입력값으로 사용
- 기능적 응집도(Functional): 단일한 목적 수행

## 디자인 패턴

- 생성패턴
    - 객체 생성에 관련된 패턴
    - Singleton: 인스턴스가 하나
    - Builder: 복잡한 인스턴스를 조립하여 만드는 도구
    - Abstract Factory: 구체적인 클래스를 지정하지 않음
    - Factory: 인스턴스를 만드는 클래스를 서브클래스에서 결정
    - Prototype: 처음부터 일반적인 원형을 제작.

- 구조 패턴
    - 클래스나 객체를 조합
    - Adapter: 기존 생성된 클래스를 재사용하도록 중간에 맞춰줌
    - Bridge: 구현부와 추상부를 분리
    - Composite: 트리 구조로 부분-전체계층
    - Decorator: 기존 구현된 클래스에 기능 추가
    - Facade: 복잡한 시스템에 대하여 단순한 인터페이스 제공
    - Flyweight: 클래스의 경량화
    - Proxy: 실제 객체에 대한 대리 객체

- 행위 패턴
    - 객체나 클래스간의 책임분배와 상호작용
    - Chain of Responsibility: 요청을 처리할 수 있는 기회를 여러객체에 부여
    - Command: 요청을 객체로 캡슐화
    - Mediator: 한 집합에 속하는 객체들의 상호작용
    - Memento: 객체의 정보를 저장할 필요가 있을때 undo
    - Observer: 한 객체의 상태 변화 시 상속된 다른 객체제는 자동으로 통보하고 갱신
    - State: 객체의 내부상태가 변경될때 행동
    - Strategy: 동일 계열의 알고리즘 정의, 이들의 상호작용
    - Template Method: 알고리즘 뼈대를 정의하고 서브클래스 수행
    - Visitor: 객체 구조를 이루는 원소에 대해 수행할 연산 정의
    - Interpreter: 해당 언어로 된 문장을 해석
    - Iterator: 모든 항목에 대해 접근 가능


## 테스트 커버리지

- 문장 커버리지: 프로그램 내의 모든 명령문을 적어도 한번 수행
- 결정 커버리지: 결정 포인트 내의 {전체} 조건식이 적어도 한번은 참과 거짓의 결과 수행
- 조건 커버리지: 결정 포인트 내의 {개별} 조건식이 적어도 한번은 참과 거짓의 결과 수행
- 조건/결정 커버리지: 결정+조건
- 변경조건/결정 커버리지: 각 개별 조건식이 다른 개별조건식에 영향x
- 다중 조건 커버리지: 결정 조건 내 모든 개별 조건식의 조합을 100%보장
- 기본 경로 커버리지: 수행 가능한 모든 경로 계산


## 스키마

- 외부스키마: 사용자의 관점
- 내부스키마: 시스템 프로그래머/설계자 관점의 스키마
- 개념스키마: 기관/ 조직의 전체 관점
