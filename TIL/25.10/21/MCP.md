
# MCP
- Model Context Protocol

## 왜 MCP인가
- 외부 툴을 활용하는 연구가 급증하면서 회사/모델마다 각기 다른 툴 호출 방식 및 스키마를 개발
- 문제점
    - 호환성 부족
    - 재사용 어려움

## MCP란?
- 언어 모델이 외부 툴과 상호작용하기 위한 표준화된 방식으로 정의한 프로토콜
- 툴호출, 응답 전달, 컨텍스트 공유를 하나의 공통 규격으로 처리

## MCP아키텍처
- MCP Host: 하나 또는 여러 개의 MCP 클라이언트를 조정하고 관리하는 AI 애플리케이션
- MCP Client: MCP 서버와의 연결을 유지하며 MCP호스트가 사용할 수 있도록 MCP서버로부터 컨텍스트를 가져오는 구성요소
- MCP Server: MCP클리언트에게 컨텍스트를 제공하는 프로그램

## MCP 계층
- MCP는 두개의 계층으로 구성된다
    - 데이터 계층: 클라이언트-서버 통신을 위한 JSON-RPC 기반 프로토콜을 정의
        - 라이프 사이클 관리, 툴, 리소스, 프롬프트과 같은 핵심 요소들이 포함
    - 전송 계층: 클라이언트 서버 간 데이터 교환을 가능하게 하는 통신 메커니즘과 채널을 정의
        - 정송 방식에 특화된 연결수립, 메세지 프레이밍, 인증이 포함된다.
- 개념적으로 데이터 계층은 내부 계층, 전송 계층은 외부 계층이다.

## MCP의 장점
- 표준화
- 확장성
- 호환성
- 재사용성
- 투명성
