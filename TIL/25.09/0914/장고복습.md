# 시험 대비

1. MVC 디자인 패턴

    - 애플리케이션을 구조화하는 대표적인 패턴

    - model, view, controller

    - model

        - 데이터와 관련된 로직을 관리
    
    - Template

        - 레이아웃과 화면을 처리

        - 화면상의 사용자 인터페이스 구조와 레이아웃 정의
    
    - view

        - 모델과 템플릿과 관련한 로직을 처리해서 응답을 반환

2. 장고 요청&응답

    - 요청, url, app(view, model, template), 응답

3. Django Template Language

    - DTL

    - 템플릿에서 조건, 반복, 변수 드으이 프로그래밍적 기능을 제공하는 시스템

    - Variable

        - render 함수의 세번째 인자로 딕셔너리 데이터를 사용

    - Fillers

        - 표시할 변수를 수정할 때 사용

    - Tags

        - 반복 또는 논리를 수행하여 제어흐름을 만듦

    - comments

        - 주석

4. 템플릿 상속

    - 페이지의 공통요소를 포함하고

    - 하위 템플릿이 재정의 할수 있는 공간

5. 요청과 응답

    - action: 입력 데이터가 정송될 url을 지정

    - method: 데이터를 어떤 방식으로 보낼 것인지

    - input: 사용자의 데이터를 입력 받을 수 있는 요소

    - name: 사용자가 입력한 데이터에 붙이는 이름

    - HTTP request객체

        - form으로 전송한 데이터 뿐만 아니라 장고로 들어오는 모든 요청 데이터가 담겨있음

6. Variable Routing

    - URL 일부에 변수를 포함시키는것

7. App URL mapping

    - 각 앱에 URL을 정의하는 것

    - include()

        - 프로젝트 내부 앱들의 url을 참조할 수 있도록 매핑하는 함수

8. BASE_DIR/ 'templates'

9. Django Model

    - DB의 테이블을 정의하고 데이터를 조작할 수 있는 기능들을 제공

10. QuerySet API

    - ORM에서 데이터를 검색, 필터링, 정렬 및 그룹화 하는데 사용하는 도구

    - 파이썬의 모델 틀래스와 인스턴스를 활용헤 DB에 데이터를 저장, 조회, 수정, 삭제 하는것

11. CRUD

    - Create, Read, Update, Delete

12. 데이터 객체를 만드는법

    - Model.objects.create(~~~)

13. 데이터 조회

    - all : 전체 데이터 조회

    - filter: 주어진 매개변수와 일치하는 객체를 포한하는 쿼리셋 반환

    - get: 주어진 매개변수와 일치하는 객체를 반환

14. HTTP

    - 네크워크 상에서 데이터를 주고받기 위한 약속

    - HTTP request methods

        - 데이터에 대해 수행을 원하는 작업을 나타내는것

        - 클라이언트가 웹 서버에 특정 동작을 요청하기 위해 사용하는 표준 명령어

        - GET, POST

    - GET 메소드 특징


        - 캐싱

            - 브라우저는 GET요청의 응답을 로컬에 저장할 수 있음
            
            - 동일한 URL로 다시 요청할때 서버에 접속하지 않고 저장된 결과를 사용

            - 페이지 로딩시간 단축

    - POST 메소드 특징

        - 서버에 데이터를 제출하여 리소스를 변경 하는데 사용
        
        - GET에 비해 더 많은 양의 데이터 전송

        - POST 요청은 히스토리에 남지 않음

        - 캐시 할수 없음

        - POST 요청이 일반적으로 서버의 상태를 변경하는 작업을 수행하기 때문

15. HTTP response status code의 역할

    - 서버가 클라이언트의 요청에 대한 처리 결과를 나타내는 3자리 숫자


16. CSRF

    - 사이트 간 요청 위조

    - 사용자가 자신의 의지와 무관하게 공격자가 의도한 행동을 하여 특정 웹페이지를 보안에 취양하게 하거나 수정, 삭제 등의 작업을 하게 만드는 공격 방법

    - 요청시 토큰 값도 함께 서버로 전송 될 수 있도록 하는것

    - 인증 개념

17. 캐시

    - 데이터나 정보를 임시로 저장해두는 메모리나 디스크 공간

    - 이전에 접근한 데이터를 빠르게 검색하고 접근할 수 있도록 함

18. 유효성 검사

    - 수집한 데이터가 정확하고 유효한지 확인하는 과정


19. Form & ModelForm

    - Form: 사용자가 입력 데이터를 DB에 저장하지 않을때

    - ModelForm: 사용자가 입력 데이터를 DB에 저장해야 할때

20. Static Files

    - 서버 측에서 변경되지 않고 고정적으로 제공되는 파일

    load static tag를 사용하여 경로 할당

21. Static_url

    - 기본 경로 및 추가 경로에 위치한 정적 파일을 참조하기 위한 URL

22. Media Files

    - 사용자가 웹에서 업로드하는 정적 파일
