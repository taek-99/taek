# 문자열

## 브루트포스(Brute Force) 패턴 매칭

- 아이디어: 본문 문자열의 처음부터 끝까지 모든 위치에서 패턴을 일일이 비교.

- 시간 복잡도: 최악의 경우 O(nm) (n: 본문 길이, m: 패턴 길이).

- 장점: 구현이 매우 간단.

- 단점: 비효율적 (특히 텍스트가 크고 패턴도 긴 경우).

## 라빈-카프(Rabin–Karp) 알고리즘

- 아이디어: 해시(hash) 값을 이용해서 패턴과 본문 문자열의 부분 문자열을 비교. 부분 문자열의 해시값과 패턴 해시값이 다르면 곧바로 다음 위치로 넘어감 → 불필요한 직접 비교를 줄임. 해시 충돌 시에는 실제 문자열 비교로 보정.

- 시간 복잡도: 평균: O(n + m)/ 최악: O(nm) (모든 해시 충돌 발생 시)

- 장점: 여러 패턴을 동시에 찾을 때 유용.

## 보이어-무어(Boyer–Moore) 알고리즘

- 아이디어: 패턴의 오른쪽 끝에서 왼쪽으로 비교. 불일치가 발생하면 미리 계산된 규칙(shift table)을 이용해 패턴을 여러 칸 건너뛸 수 있음.

- 대표적인 규칙:

    - Bad Character Rule: 불일치한 문자가 패턴에 없으면 패턴을 통째로 건너뜀.

    - Good Suffix Rule: 일치한 접미사를 기준으로 점프.

- 시간 복잡도: 평균: O(n/m) (아주 빠름)/ 최악: O(nm)

- 장점: 실제 텍스트 검색에서 가장 빠른 축에 속함.

## KMP(Knuth–Morris–Pratt) 알고리즘

- 아이디어: 불일치가 발생했을 때, 이미 일치했던 접두사 정보를 활용해 비교 위치를 효율적으로 이동. "실패 함수(Failure function)" 또는 "LPS(Longest Prefix Suffix)" 배열을 미리 계산해두고 활용.

- 시간 복잡도: 전처리: O(m)/ 검색: O(n)

- 장점: 항상 선형 시간 보장 (최악의 경우에도 O(n)).
