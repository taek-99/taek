# JWT

## Json Web Token
- 유저가 스스로 누군지 증명하는 디지털 출입증
- 서버가 유저에게 발급해주는 긴 문자열

## JWT 구조
- Header 
    - 어떤 알고리즘으로 암호화했는지 적혀있는 봉투 역할

- Payload
    - 실제 유저가 들어있는 내용물

- Signature
    - 정보가 조작되지 않았음을 증명하는 위조 방지 도장


## JWT 동작 흐름
- 클라이언트: 로그인 요청
- 서버: 사용자 정보 검증 후 JWT 토큰 발급
- 사용자는 JWT를 브라우저나 앱에 저장
- 발급받은 JWT를 header에 담아 API 요청
- 별도의 DB 조회 없이 JWT에 포함된 서명을 검증 후 응답

## JWT 특징
- 장점
    - 서버 부담이 적음
    - 확장성이 좋음
    - 모바일 친화적

- 단점
    - 키를 잃어버렸을 경우 대응하기 어려움
    - 실수로 payload에 개인정보가 있을 시 누구도 확인할 수 있음


## Token 방식 vs JWT방식
- Token
    - 키 자체에는 아무런 정보가 없고, 서버가 가지고 있음
    - DB 저장된 정보를 확인하여 사용자 인증
    - 로그인 관리가 엄격해야하는 경우 사용

- JWT
    - 키에 정보가 들어있어 서버가 정보를 따로 확인할 필요가 없음
    - 서버가 토큰을 해석해서 사용자 인증을 하게됨
    - 간단하지만 유출시 대응하기 힘듬
